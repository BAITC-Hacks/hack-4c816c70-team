# Работа над фронтендом

Продукт: «Аким на 5 часов». Стек уже выбран: Next.js App Router, React, TypeScript strict. Сохраняйте существующий `app/`; не создавайте второй проект и не переносите всё в `src/`.

Прочитайте `docs/architecture.md`, `docs/design.md`, `docs/acceptance.md`, затем своё задание в `docs/tasks/`. Пути в этих документах считаются от `frontend/`, если явно не сказано иначе.

Общие интерфейсы находятся в `lib/contracts/ui.ts`. Это внутренний контракт компонентов, не Swagger. Изменения интерфейсов обсуждаются до правки; адаптацию под реальный API делает GPT. Только GPT меняет `package.json` и lockfile. Каждый исполнитель пишет свой отчёт в `docs/reports/claude-1.md`, `claude-2.md` или `gpt.md`.

## Обязательные правила

- Источник сетевого контракта — опубликованный Swagger и корневой `docs/api.md`. Не выдавайте предложенные поля за реализованные.
- C# рассчитывает Score, лаги, эффекты, синергии, районные баллы и окончательную валидность. Не переносите формулу в браузер, Next route handlers или Server Actions.
- Браузер может считать количество выбранных мер и предварительную сумму их цен для формы. Финальные расходы берите из ответа сервера. Прогнозные показатели не вычисляйте.
- Все пользовательские строки — на русском. Названия районов и значения загружайте через API или явно включённый тестовый fixture.
- Не подменяйте недоступный API успешным mock-ответом. Mock включается явно, обозначается в интерфейсе и не считается интеграционной приёмкой.
- Нет LLM-ключей и вызовов OpenAI в браузере. Объяснение приходит вместе с результатом C# API.
- Не редактируйте `backend/`, корневой `docs/api.md`, compose, корневой README и THIRD_PARTY: передавайте изменения их владельцам через отчёт.
- Новая библиотека требует конкретной причины. Основа — CSS Modules, CSS variables, native fetch, React Context + reducer, SVG. Не добавляйте второй UI kit или state manager.
- Не перезаписывайте чужие изменения. При общем каталоге не переключайте ветки, пока другой аккаунт работает в нём. Для параллельной работы используйте отдельные клоны или worktree.
- Не делайте force push. Перед передачей фиксируйте commit, изменённые файлы, проверки и оставшиеся проблемы.

## Критерий завершения

Код принят после lint, typecheck, production build, проверки своей функциональности и просмотра в браузере на desktop/mobile. Если проверка не выполнена, явно укажите это в отчёте. Наличие красивого скриншота не заменяет работающий сценарий.
