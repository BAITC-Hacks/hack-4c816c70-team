# Приёмка фронтенда

Статус этого файла — чек-лист будущей реализации. Пункты не считаются выполненными, пока в отчёте нет результата проверки.

## Проверка архитектуры

- [ ] Один набор choices, один API client, один слой DTO -> UI.
- [ ] Нет формулы Score, расчёта лагов, синергий или районных баллов во frontend.
- [ ] Никаких чисел датасета в JSX: API/явные fixtures передают данные через props.
- [ ] DTO соответствуют опубликованному Swagger; недостающие поля не выдаются за нули.
- [ ] Browser fetch использует NEXT_PUBLIC_API_URL; Next rewrites и API_INTERNAL_URL отсутствуют.
- [ ] Display-only дельты равны разнице значений API; формула Score и эффекты не пересчитываются.
- [ ] UI-модули не импортируют внутренности соседних features и не вызывают fetch.
- [ ] Только GPT меняет dependencies/config; изменения backend и корневых файлов согласованы с владельцами.

## Сценарии выбора

| Случай | Ожидаемое поведение |
| --- | --- |
| 0, 4 или 6 мер | Нельзя оценить; сервер тоже отклоняет неверное число |
| Одна мера дважды, даже в разных районах | Повтор отклоняется |
| M7 + M8 + M9 | Превышен лимит двух мер соцсферы |
| Сумма ровно 100 | Бюджет допустим при выполнении остальных правил |
| Сумма 101 или больше | Причина показана; POST в обход UI отклоняется сервером |
| M1 в Нуре + M3 в Есиле | Глобальная несовместимость |
| M4 и M7 в Нуре | Конфликт за участок |
| M4 в Есиле и M7 в Нуре | Эта пара допустима; остальные правила проверяются отдельно |
| M5 и M13 в Сарыарке | Конфликт программ |
| M5 в Сарыарке и M13 в Алматы | Эта пара допустима |
| Районная мера без района | Черновик виден; evaluate заблокирован |
| Неизвестный район или measureId | Ошибка, без попытки угадать значение |
| Городская M12 | Select района скрыт; ключ districtId отсутствует в JSON |
| Удаление меры | Бюджет/ограничения сразу обновляются, карточка доступна снова |
| Смена района выбранной меры | Конфликты пересчитываются для нового назначения |
| 5 допустимых мер из 3–4 направлений | Можно оценить; не требуется все 5 направлений |

Контрольный набор: M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка. На реальном API: 95 потрачено, 5 осталось, 52,56 → примерно 56,54, синергия M10/M12 в Нуре. Отдельно изменить одну меру и повторить оценку: результат должен прийти новым запросом и соответствовать новому набору.

## Сеть и результат

- [ ] Scenario загружается; видны 5 районов, 10 показателей, 14 мероприятий.
- [ ] GET failure имеет повтор; нет выдуманного исходного Score.
- [ ] POST pending блокирует двойной клик и изменение отправленного набора.
- [ ] Ошибки 400 и 422 показывают API message и сохраняют choices.
- [ ] Timeout, потеря сети, 500 и неверный JSON дают понятную ошибку; UI не падает.
- [ ] Старый ответ после сброса/нового запроса игнорируется.
- [ ] После возврата и редактирования старый результат не выдаётся за актуальный.
- [ ] Финальные spent/remaining берутся из ответа API.
- [ ] Все 5 районов и все 10 показателей доступны «до / после».
- [ ] Уменьшение показателя отображается явно, например эффект T1 у M11.
- [ ] Значение 40 не подсвечивается как строго ниже 40.
- [ ] Фронт показывает explanation сервера и реальные appliedSynergies; appliedEffects равен null, раздел отдельных эффектов скрыт.
- [ ] В scenario нет районного Score: обзорные карточки показывают исходные показатели, без собственного агрегирования.
- [ ] Mock-объяснение от сервера после сбоя live LLM отображается с полученными числовыми результатами; frontend не включает свои fixtures.
- [ ] Backend с LLM_MODE=mock работает через настоящий API без OPENAI_API_KEY.
- [ ] Frontend fixture включается явно и виден как «Демонстрационные данные»; API error не включает его автоматически.

## Автоматические проверки

GPT добавляет `typecheck` и тестовые scripts, если их ещё нет. Обязательные проверки из `frontend/`:

```bash
npm ci
npm run lint
npm run typecheck
npm run build
```

Сейчас `typecheck` и test scripts в исходном package.json ещё отсутствуют. До их добавления для типов можно использовать локальный `tsc --noEmit` после генерации Next types; не описывайте несуществующий script как уже работающий.

Тесты Claude 2: таблица конфликтов и пограничные случаи validateDraft. Тесты GPT: payload городской меры, нормализация API ошибок, игнорирование устаревшего ответа, сквозной контрольный набор. Тестируйте поведение, не CSS-классы и не точную структуру JSX. Тесты с перехваченным HTTP не заменяют хотя бы один запуск с реальным C# API.
