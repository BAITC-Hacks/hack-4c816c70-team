# Запуск города в браузере

На скриншоте пользователя была резервная SVG-схема при широком окне. Точную причину в его браузере не удалось измерить. В коде обнаружены молчаливая блокировка по hardwareConcurrency/deviceMemory ≤ 2, сохранение отрицательного результата до перезагрузки и отсутствие сообщения при отказе WebGL.

Исправлено:
- Возможность запуска проверяет сам Three.js renderer, без эвристики количества ядер/памяти и без лишнего пробного WebGL-контекста.
- Переход через 900 px отслеживается через matchMedia; расширение окна больше не требует reload.
- При экономии трафика доступен явный запуск; при ошибке — локализованное объяснение и повторная попытка.
- Резервная картинка — собственные снимки той же модели днём/ночью из передачи Claude 1. Текст явно сообщает, что это снимок, а выбор района доступен через DOM.
- Сохранены ленивый импорт, reduced motion, render-on-demand и освобождение сцены.

Проверки: lint, 55 тестов, production build с TypeScript успешны. На локальной production-сборке: 390 px — canvas 0 и нет overflow; расширение до 1440 без reload — canvas 1, город виден, смена темы работает. API на временном порту 3011 не подключён; полный сценарий там не заявляется проверенным. Фактический отказ WebGL и браузер пользователя требуют отдельного прогона.

Публикация: отдельное обновление frontend по зафиксированному SHA; API не пересоздавать.
