## Что работает

**validateDraft.** Проверяет только ограничения выбора, все правила берёт из `scenario.rules`:
- `rules === null` → единственная ошибка `rules-unavailable`, `canSubmit: false`;
- `choice-count`: ровно `requiredChoices`;
- `duplicate-measure`: повтор меры отклоняется и в разных районах;
- `unknown-measure`;
- `district-required`: `undefined`, `""` и `null` считаются отсутствием района;
- `invalid-district`: чужой ID района, без попыток угадать;
- `district-for-city`: у городской меры есть любое значение `districtId`;
- `budget-exceeded`: строго `spent > budget`, ровно 100 допустимо, цены не округляются;
- `category-limit`: больше `maxPerCategory` уникальных мер одного направления;
- `incompatible`: `global` — пара в любых районах; `same-district` — только при совпадении `districtId`, для каждого района своя ошибка.

`provisionalSpent` и `provisionalRemaining` — это только сумма цен каталога для формы.

**Planner:**
- Каталог из `scenario.measures`, фильтр «Все» + 5 направлений с счётчиком `N/2`. Переключение фильтра не трогает choices.
- На карточке: направление и ID, название, охват «Район / Весь город», цена, лаг, эффекты с подписью «Полный эффект из каталога, без учёта лага». Отрицательный эффект (T1 у M11) выделен знаком ▼ и цветом.
- Select района есть только у районной меры, районы берутся из `scenario.districts`. `preferredDistrictId` подставляется в новые карточки, если не конфликтует, и об этом есть видимая строка. Назначение редактируется в карточке и в слоте.
- Городская мера создаётся как `{ measureId }`: ключа `districtId` нет, в JSON его тоже нет. Сброс района у районной меры тоже удаляет ключ.
- Районную меру можно добавить без района: слот помечается «Район не выбран», оценка блокируется.
- M1/M3 блокирует всю карточку с причиной «Нельзя вместе с M…». M4/M7 и M5/M13 делают недоступным только конкретный район в select, с текстом «Недоступно — Нура: уже выбрана M4. …». Остальные районы и карточка остаются доступными. При смене района или удалении меры всё пересчитывается сразу.
- Причины блокировки показаны текстом под действием, без tooltip: заполнено 5 из 5, лимит направления, глобальная несовместимость, «Недостаточно бюджета: не хватает N ед.», конфликт во всех районах.

## Исправление после ревью: заранее выбранный район

Дефект: в карточке M7 вручную выбрана Нура, затем M4 добавлена в Нуру. Кнопка «Добавить» у M7 оставалась активной, и M7 сохранялась с конфликтующим назначением. Причина: `getAddAvailability` не учитывала район, выбранный в карточке до добавления.

Исправление: `getAddAvailability(scenario, choices, measureId, districtId = "")` теперь принимает этот район. Если назначение конфликтует («В районе «Нура» уже выбрана M4. … Выберите другой район.») или район неизвестен, добавление блокируется. Для city-меры район игнорируется, «без района» по-прежнему допустимо. `Planner` передаёт этот район и в отображение карточки, и в проверку внутри `handleAdd`. Select остаётся доступным: смена района сразу снимает блокировку.

Проверено в harness: Нура для M7 → M4 в Нуру → кнопка M7 disabled, причина видна текстом и связана через `aria-describedby`, клик не меняет payload. После смены на Есиль кнопка активна, payload — `[{M4, nura}, {M7, yesil}]`. Lint, typecheck и `npm test` (35/35) проходят.

## Замечания и решения, о которых стоит знать

1. `serverError` показывается под заголовком «Ответ сервера» — одинаково для 400/422 и сетевых ошибок. Если GPT захочет разные заголовки, нужен отдельный prop; это изменение контракта, его нужно согласовать.
2. Районный конфликт через UI создать нельзя: опции с конфликтом disabled. `validateDraft` всё равно ловит такие choices, если они придут от родителя.
3. «Возможная синергия» показывается при наличии обеих мер пары, без учёта района. Это справка; фактическое применение — `appliedSynergies` из ответа.
4. Подписи направлений (`labels.ts`: «Транспорт», «Экология», «Социальная сфера», «Безопасность», «Городские сервисы») — UI-строки, не данные. Если у Claude 1 или в results другие формулировки, стоит договориться об общем словаре.
5. В `frontend/AGENTS.md` появился блок `<!-- BEGIN:nextjs-agent-rules -->`. Его дописывает `next dev`, скорее всего чужой сервер на :3107 в `frontend/`. Мой harness писал свой AGENTS.md в scratchpad. Сам файл я не трогал; решение за владельцем (архитектор).
