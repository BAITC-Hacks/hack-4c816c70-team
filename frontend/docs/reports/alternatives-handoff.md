# Handoff UI: `POST /api/simulations/alternatives`

Дата: 23.09.2026. Код не менялся.

Примечание интегратора: это описание контракта и желаемого поведения, а не браузерная приёмка экрана. UI уже подключён в `88a0c8c`. При сверке кода обнаружены два различия с рекомендациями ниже: ранее найденные карточки скрываются во время повторного поиска и после его ошибки; описание замены строится из разницы choices с переводом известных названий, а не из `change.text`. Исходный оценённый план при этом сохраняется. Эти различия не меняют расчёт или контракт и не заявлены как исправленные.

## Граница функции

`POST /api/simulations/alternatives` ищет варианты **только среди замен одной из пяти выбранных мер**, включая перенос районной меры в другой район. Ответ всегда помечен `searchScope: "single_swap"`.

В UI нельзя называть результат «оптимальным планом» или «глобальным оптимумом». Корректное название из API: «Лучший найденный вариант среди замен одной меры» / «Бір шараны ауыстыру нұсқаларының ішінде табылған ең жақсы нұсқа» / «Best option found among single-measure replacements».

## Запрос

```http
POST /api/simulations/alternatives
Content-Type: application/json
Accept-Language: ru-RU | kk-KZ | en-US
```

```json
{
  "choices": [
    { "measureId": "M7", "districtId": "nura" },
    { "measureId": "M8", "districtId": "nura" },
    { "measureId": "M10", "districtId": "nura" },
    { "measureId": "M12" },
    { "measureId": "M5", "districtId": "saryarka" }
  ],
  "goal": "score"
}
```

- Передавать текущие пять `choices` без клиентских преобразований и один из `goal`: `score`, `equity`, `economy`.
- `score` означает больший `score`; `equity` — больший `breakdown.minDistrictScore`; `economy` — меньший `spent`.
- `Accept-Language` берётся из `useLocale().intlLocale`. Сервер возвращает фактический язык в `locale` и `Content-Language`; текстовые поля уже локализованы сервером.
- Не пересчитывать варианты, дельты или их порядок на клиенте. `delta` уже равен «вариант минус исходный план» с серверным правилом округления; у `delta.spent` положительное значение означает большие расходы.
- Ошибки валидного плана совпадают с `/evaluate`; дополнительно отсутствующий/неизвестный `goal` даёт `400 INVALID_GOAL`.

## Ответ и отображение

| Поле | Для UI |
| --- | --- |
| `goal`, `searchScope`, `candidatesChecked`, `validCandidates`, `locale` | Контекст поиска. `searchScope` не скрывать в смысловом тексте: это замены одной меры. |
| `original` | Снимок исходного плана: `choices`, `spent`, `remaining`, `score`, `breakdown`, районные `score`. Хранить отдельно для сравнения; не подменять им текущий state. |
| `bestByGoal` | ID лучшего варианта для каждой цели или `null`, если для цели нет строгого улучшения. Это указатели на `variants`, не три независимых плана. |
| `variants` | До трёх уникальных карточек. У карточки: `id`, массив `strategies`, серверный `title`, `plan`, `change`, `delta`, `arguments`, `tradeoffs`. Один план может обслуживать несколько `strategies`; не дублировать карточку. |
| `change` | `kind: "replace"` или `"move"`; для городской меры `districtId: null`. Показывать серверный `change.text`, а не строить фразу из ID. |
| `plan` | Готовый полный план из пяти choices и рассчитанные сервером числа. Показывать их как сравнение с `original`; не вызывать `/evaluate` для предпросмотра. |
| `arguments`, `tradeoffs` | Проверенные сервером факты. Показывать оба списка: особенно у цели `economy` нельзя скрывать снижение Score/самого слабого района. |
| `recommendation` | Совет для **запрошенного** `goal`: `status`, `variantId`, `title`, `text`, `arguments`, `tradeoffs`, `source`. Использовать `variantId` только как ссылку на существующую карточку. |

## Состояния

1. **Idle.** На экране результата доступна кнопка поиска и выбор цели. Запрос возможен только при имеющемся актуальном результате и пяти валидных choices.
2. **Loading.** Блокировать повторный запуск и изменение цели для этого запроса. Сохранять видимыми исходный результат, текущие choices и уже полученные карточки; не заменять план placeholder-данными. Отменённый/устаревший ответ игнорировать тем же request/revision-подходом, что и evaluate.
3. **Improved.** При `recommendation.status: "improved"` показать серверный совет для выбранной цели и карточки из `variants` (не более трёх, без дублей по `id`). `recommendation.source: "llm"` — «AI-анализ» / «AI-талдау» / «AI analysis»; `mock` — «Шаблонное объяснение» / «Үлгілік түсіндірме» / «Template explanation». Не приписывать модели числа или сам поиск: числа и варианты серверные.
4. **No improvement.** При `recommendation.status: "no_improvement"` это успешный ответ, не ошибка. Показать `recommendation.text`; `variantId` равен `null`, `arguments` и `tradeoffs` пусты. Это означает отсутствие строгого улучшения **выбранной цели среди замен одной меры**. В том же ответе могут быть карточки для других целей (`variants` не обязан быть пустым) — их можно показать с их `strategies`, но не выдавать за улучшение текущей цели.
5. **Error.** Для network/timeout/HTTP/contract error сохранить исходный результат, choices и ранее показанные карточки; показать локализованный баннер и Retry. Не подменять ошибку fixture и не очищать текущий план.

## Применение варианта

- Единственный допустимый payload применения — выбранный пользователем `variant.plan.choices` целиком, включая порядок с заменённым слотом.
- Кнопка применения должна быть отдельным явным действием на карточке. Загрузка, ошибка или появление карточки никогда не изменяют `choices` автоматически.
- После явного применения заменить черновик на `variant.plan.choices`, сохранить `original` только для визуального сравнения до ухода с экрана, пометить прежний результат неактуальным и предложить/перевести к повторной оценке. Не переносить `variant.plan` в основной результат как будто он уже был оценён пользователем.
- Если применение отменено, запрос упал или пришёл устаревший ответ, текущий черновик и результат остаются без изменений.

## Контрольный пример

Для контрольного плана (`95`, `56.54`) сервер в mock возвращает две уникальные карточки:

- `alt_M5_M3_nura`: `strategies: ["score", "equity"]`, расходы `100`, Score `57.21`;
- `alt_M5_M11_nura`: `strategies: ["economy"]`, расходы `80`, Score `56.69`.

Это примеры лучшего результата в ограниченном `single_swap` поиске, не доказательство оптимальности всех пятимерных планов.
