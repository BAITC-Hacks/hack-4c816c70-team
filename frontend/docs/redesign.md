# Редизайн: минимализм, движение и три страницы

Актуальная поправка пользователя от 23 сентября. Этот документ заменяет прежние визуальные ограничения design.md и одноэкранную навигацию architecture.md. API, правила выбора и границы ответственности сохраняются. Цель — готовая демонстрация к 17:30, 18:00 только резерв.

## Общее направление

Спокойный современный городской интерфейс: выразительная типографика, свободное пространство, тонкие разделители, один акцент, ясная иерархия. Убрать ощущение длинной административной формы и одинаковых коробок. Декор поддерживает работу с районами и решениями. Контент и действия остаются видимыми без завершения анимации.

- Контейнер 1200–1280 px, поля 24–40 px на desktop и 16 px на mobile. Между крупными секциями 80–112 px на главной, 32–48 px в рабочих экранах.
- Три темы: светлая «День», тёмная «Ночь», тёплая «Бумага». Режим «Системная» выбирает день/ночь по ОС. Все цвета через существующие семантические CSS tokens; сохранить их имена для совместимости.
- Шрифт Manrope с кириллицей для заголовков и интерфейса, системный fallback; цифры tabular-nums. Одна семья, максимум три начертания. GPT подключает локальные WOFF2 через next/font/local и фиксирует лицензию/источник в отчёте владельцу THIRD_PARTY. Если легально полученного файла нет — временно системный стек, сборка не должна требовать загрузки шрифта из сети.
- Главный заголовок 56–80 px desktop и 36–44 px mobile, основной текст 16 px, длинный текст до 65–72 символов в строке. Контраст обычного текста минимум 4.5:1, крупного 3:1.

## Страницы

`/` — главная и обзор. Первый экран: «Пять решений. Один город.»; краткое объяснение, основной CTA «Принять решения», бюджет, исходный Score из API. Дальше блок «Как это работает» из трёх шагов, обзор пяти районов с существующей схемой и исходными показателями, заключительный CTA. Пользователь может сразу начать; прокрутка не обязательна. Не добавлять выдуманные отзывы, статистику или достижения. Если API недоступен, вводный контент остаётся доступен, сценарные данные имеют явное состояние ошибки/повтора.

`/decisions` — рабочий экран. Один h1, фильтры направлений, компактный каталог и постоянное резюме плана. В карточке сразу видны название, цена, охват, лаг и действие. Полный список эффектов можно раскрывать через «Подробнее», отрицательный эффект и причина блокировки не прячутся. Выбор района доступен только районной мере. Desktop: каталог + sticky summary; mobile: нижняя компактная панель количества/остатка/CTA и раскрываемый список выбранного, без перекрытия контента и фокуса.

`/results` — спокойный отчёт: крупный Score до/после и дельта, расходы, сравнение районов, раскрываемые показатели, синергии, объяснение сервера. Визуальные полосы строятся по полученным значениям 0–100, числа видны сразу. Кнопки «Изменить решения» и «Начать заново». При прямом открытии без результата — честное пустое состояние со ссылкой на решения, без фальшивой оценки.

## Движение

- Шапка sticky, мягко меняет фон/границу при прокрутке, активная страница имеет анимированный индикатор. Не менять высоту так, чтобы прыгал контент; не прятать навигацию в момент взаимодействия.
- Блоки главной появляются при прокрутке: opacity + translateY 12–20 px, 350–500 ms, сдвиг между соседями 60–80 ms. IntersectionObserver, один раз; при отсутствии JS контент виден. Не скрывать ссылку, получившую клавиатурный фокус.
- Карточки: hover/focus 140–180 ms, выделение выбранной меры 180–240 ms. Можно коротко подсветить обновившийся бюджет. Не анимировать вычисление Score или создавать видимость промежуточных серверных результатов.
- Переходы страниц: короткое появление нового содержимого, без задержки навигации и блокировки кликов. Не вводить scroll hijacking, непрерывный parallax, фоновые видео или тяжёлый WebGL.
- `prefers-reduced-motion`: без перемещений, каскада и smooth scroll; вся информация и управление сразу доступны. Основная реализация CSS + IntersectionObserver, отдельная библиотека анимаций пока не нужна.

## Архитектура и общие интерфейсы

GPT создаёт общий клиентский SimulationProvider в сохраняемом layout: ровно один вызов useSimulation, один reducer и единый снимок отправленного набора. Страницы становятся тонкими контейнерами для существующих CityOverview/Planner/Results. URL — источник текущего экрана; не оставлять конкурирующие step и pathname. Back/Forward работают без потери выбора. При изменении набора предыдущий результат недействителен.

Черновик можно восстанавливать из sessionStorage (версия схемы, проверка IDs/правил после получения scenario, доступность хранилища проверяется). Ответ расчёта не восстанавливать из старого хранилища как свежий. После reload /results показать пустое состояние, если актуального результата в памяти нет. Не отправлять POST автоматически при переходе, reload или восстановлении.

Claude 1 владеет `components/ui/`, `styles/`, `features/city-overview/`, `public/city/`. Он создаёт ThemeSwitcher, ThemeProvider и Reveal в components/ui с экспортами из index; ThemeProvider принимает children, тему хранит под ключом `akim-theme`, использует data-theme на html со значениями light/dark/paper. Системный режим — предпочтение, а не четвёртая палитра. GPT монтирует ThemeProvider и согласованный ранний theme bootstrap в app/layout, исключает вспышку неверной темы и hydration mismatch. ThemeSwitcher сам использует контекст. Не размазывать темы по локальным цветам компонентов.

AppHeader сохраняет прежние props, может добавить необязательный `href` в тип элемента steps. При наличии href использует Next Link с реальным адресом и aria-current="page"; disabled пункт остаётся недоступным и объяснимым. GPT передаёт /, /decisions, /results, pathname и доступность результата. Существующие потребители должны продолжать собираться. Об изменениях экспорта сразу сообщить GPT.

Claude 2 изменяет только planner и свой отчёт, использует общие tokens. GPT владеет app, simulator, results, API, конфигурацией и шрифтами `public/fonts/`. Пакеты и lockfile меняет только GPT. В общей рабочей копии коммит/push выполняет только GPT, после проверки diff; агенты не переключают ветки и не откатывают чужой код.

1. Claude 1: применить доступные навыки frontend-design и react-best-practices; vercel-composition-patterns только для общих компонентов, где нужен составной интерфейс. 2. Claude 2: frontend-design + react-best-practices; компактный Planner, отступы, h1, sticky/mobile summary, содержательные микровзаимодействия и доступность. Сохранить selection-rules и регрессию конфликтующего района. Пока Claude 1 работает — использовать существующие имена tokens, не создавать отдельную палитру.
3. GPT: маршруты и общий provider, сохранение черновика/guard результата, монтаж темы и шрифтов, новый Results. Сначала маршруты и состояние, затем визуальная полировка. Прочитать локальные документы установленного Next перед изменением роутинга. Прямой browser fetch через NEXT_PUBLIC_API_URL сохраняется; временный адрес туннеля хранится в игнорируемом .env.local.
