# Задание Claude 2 — конструктор пяти решений

Передайте этот файл второму аккаунту Claude целиком. Рабочий проект — репозиторий BAITC-Hacks/hack-4c816c70-team, каталог `frontend/`.

Ты реализуешь Planner для «Аким на 5 часов». Прочитай `AGENTS.md`, `docs/architecture.md`, `docs/design.md`, `docs/acceptance.md`, `lib/contracts/ui.ts`. Владелец визуальных примитивов — Claude 1, интеграции — GPT.

## Твоя область

Редактируй только `features/planner/` и `docs/reports/claude-2.md`. Тесты логики размести рядом с `selection-rules.ts`; тестовый runner и scripts добавляет GPT. Не меняй app, общие типы, зависимости, tokens, API или другие features.

## Публичный интерфейс

- `Planner(props: PlannerProps)` из `features/planner/index.ts`.
- `validateDraft`, соответствующая типу `ValidateDraft`, из того же index.
- `choices` приходят от родителя. Любое редактирование возвращает новый массив через `onChoicesChange`; собственный дублирующий store запрещён.
- Локальное состояние допустимо для фильтра, раскрытых карточек и поисковой строки.

## Что сделать

1. Каталог из scenario.measures с фильтром по пяти направлениям. Карточка показывает название, scope, cost, lagQuarters и полные эффекты из каталога с честной подписью.
2. Районный select появляется только для районной меры. ID и названия берутся из scenario.districts. `preferredDistrictId` можно предложить по умолчанию, но назначение видно пользователю.
3. Выбранная мера существует один раз. Пять слотов показывают меру, назначение района, стоимость и удаление. Переключение фильтра не сбрасывает выбор.
4. Для city-меры ключ districtId убирается из черновика. Незавершённая district-мера может быть видна в черновике, но оценка заблокирована.
5. Показывай предварительные расходы и остаток, количество N из 5. Не округляй исходные данные ради валидации. Кнопка оценки вызывает onEvaluate только для допустимого набора и при `!isEvaluating`.
6. `validateDraft` проверяет число, уникальность, известные ID, назначение района, бюджет, лимит направления и несовместимости. Все правила читаются из scenario.rules. При `rules === null` возвращай `rules-unavailable`, не считай набор допустимым.
7. Глобальный конфликт M1/M3 блокирует добавление в любой район. Конфликт same-district блокирует только конкретное назначение района, а не всю карточку. При изменении района всё пересчитывается.
8. Причины недоступности видны текстом рядом с действием, доступны без hover. Выбранные меры всегда можно удалить, кроме периода отправки.
9. Во время isEvaluating блокируй изменения и повторную отправку. Отображай serverError отдельно от локальных ошибок; не удаляй choices из-за API error.
10. На desktop — каталог и боковая панель, на mobile — список и компактная нижняя панель, не закрывающая контент.

## Тесты

Покрой разницу глобального и районного конфликта, смену района, ровно 100 и больше 100, повтор меры в разных районах, третью меру направления, отсутствующий/чужой район, city с districtId, 4/5/6 мер, отсутствие правил. Для fixtures используй минимальные сценарии и явно обозначай их тестовое назначение.

Не вычисляй Score, районные баллы, реализованные эффекты или синергические бонусы. Можно показывать наличие потенциальной синергической пары как справку, без прогнозных чисел. Окончательное решение принимает C# API.

## Передача

Первым передай сигнатуры, validateDraft и каркас Planner, затем полный UI. Не жди готовности API для работы по props. Если примитивов ещё нет, используй стандартные HTML-элементы со своими CSS Modules и согласованными CSS variables; не создавай второй UI kit.

В отчёте `docs/reports/claude-2.md` укажи commit, exports, изменённые файлы, проверенные сценарии, необходимые зависимости для тестов и оставшиеся дефекты. Не называй тесты пройденными без запуска. Коммит/push каждые 30 минут по регламенту, без force push.
