# Разделение работы команды

| Роль | Свои файлы | Первый результат |
| --- | --- | --- |
| Тамерлан, C# | `backend/`, `docs/api.md` | Swagger с контрактом, затем валидатор и расчёт |
| Фронтенд-разработчик, Next.js | `frontend/` | Выбор пяти мер и экран результата по API |
| Сервер и интеграция | `docker-compose.yml`, `.env.example`, корневой `README.md`, `THIRD_PARTY.md`, `docs/` для проверки | Запуск одной командой и сквозная проверка |

Фронтенд начинает по `docs/api.md`; изменение полей сразу согласуется с обоими участниками. Каждый работает преимущественно в своей области. Общие файлы меняются после `git pull --rebase`, без принудительного push в `main`.

Контрольные точки: рабочий контракт API, подключённый интерфейс, полный сценарий, чистый запуск по README. Коммит и push — не реже раза в 30 минут. Финальную проверку начинать в 17:15; последний push сделать до 17:55.

Перед каждым коммитом проверять, что в индекс не попали `.env`, `node_modules`, `bin`, `obj` и ключи. Сторонние пакеты, модели, датасеты и шаблоны добавлять в `THIRD_PARTY.md`.
