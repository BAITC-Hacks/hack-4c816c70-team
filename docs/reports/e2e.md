## Проверка языков explanation (23.09.2026)

Воспроизводимый API-прогон: `python3 backend/scripts/verify-explanation-locales.py`. **487 проверок, 27 сценариев — успешно**, сборка без ошибок и предупреждений. Для каждой локали `ru-RU` / `kk-KZ` / `en-US` проверены mock, принятый порядок AI через локальную заглушку, fallback после HTTP 401 и fallback после неверного порядка ID. Реальный ключ не использовался; внешних запросов OpenAI в этом прогоне нет.

- Во всех языках: `spent=95`, `remaining=5`, `score=56.54`. Числовые поля и данные районов вне explanation одинаковы.
- Все четыре поля explanation локализованы; `explanationLocale` и `Content-Language` совпадают с выбранным языком даже при fallback.
- Проверены приоритеты `Accept-Language`, короткие/региональные теги, отсутствие заголовка, неподдерживаемые и некорректные значения, Swagger.
- Текст ru/kk использует десятичную запятую, en — точку; английское объяснение не содержит кириллицы. Проверка выполнялась с `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=true`.
- GPT по-прежнему задаёт только порядок ID через Responses API. Текст и переводы формирует сервер. Последний настоящий live-прогон до добавления локалей: HTTP 200, `llm`, 1,95 с, одна попытка (результат backend-исполнителя).
- Дефект 3 исправлен форматированием текста. Для дефекта 7 в схеме теперь `minItems=maxItems=число утверждений`; неправильная перестановка всё равно отклоняется. Принятая схема подтверждена указанным live-прогоном. Новая браузерная проверка переключателя языков не проводилась: здесь проверен контракт API.

1. Открыть http://localhost:3000 в окне шириной 390 px.
2. Нажать «Перейти к решениям».
3. Прокрутить страницу вправо или выполнить в консоли `scrollTo(50, 0); scrollX`.

Ожидается: страница не прокручивается по горизонтали. Факт: `scrollX = 4`, `scrollWidth` 379 при `clientWidth` 375; внизу видна горизонтальная полоса прокрутки (`e2e/mobile-390-planner.png`).

Причина: в мобильном медиазапросе у строки фильтров отрицательный внешний отступ, который выходит за контейнер.

- Файл: `frontend/features/planner/planner.module.css`, правило `.filters` в строках 589–595 (`margin: 0 calc(-1 * var(--space-1, 4px))`).
- Элемент: `div.filters`, левая граница −4 px.

Исправление за разработчиком frontend: убрать отрицательный отступ или скрыть переполнение у родителя.

## Замечания

2. **Подпись для `mock` не говорит, что AI не сработал.** Сейчас в режиме `live` при ошибке OpenAI (401) пользователь видит «Серверное объяснение по расчёту» и не знает, что это шаблон, а не текст модели. Файл: `frontend/features/results/Explanation.tsx`, строка 6. Предложение: для `mock` писать, например, «Шаблонное объяснение по расчёту (без AI)».
3. **Разный формат чисел.** Карточки показывают `56,54`, а текст объяснения от сервера — `56.54`. Текст формирует backend (`ExplanationBuilder`), поэтому это решение для роли 1, а не для frontend.
4. **Нет favicon.** `GET /favicon.ico` → `404`, ошибка в консоли. Место: `frontend/app/` (нет `icon` или `favicon.ico`).
5. **Перенос счётчика в корзине на мобильном.** В развёрнутой корзине при 390 px заголовок «5 из 5» переносится на две строки (`e2e/mobile-390-tray.png`). Файл: `frontend/features/planner/DecisionTray.tsx` и стили `.tray` в `planner.module.css`.

## Не проверено

- Таймаут клиента 75 с (`frontend/lib/api/client.ts`): замедленный ответ не имитировался.
- Реальное мобильное устройство или эмуляция touch-профиля; только окно шириной 390 px.
- Ширина 390 px в режиме `llm`: результат с AI снят только на desktop.
